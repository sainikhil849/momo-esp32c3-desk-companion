MOMO 2.2 - TEST REPORT (12 Oct 2026)
====================================

Summary: 513 automatic checks passed, 0 failed (154 of them new for 2.2).
The real firmware compiles with no warnings from Momo's code in all 5
builds, and ran on Espressif's ESP32-C3 emulator through every menu, game,
reminder and alarm plus the new back button, head rub, charger, low battery,
sleep and wake-up: no crash, no memory loss. All 15 printed parts pass the
fit, overhang and collision checks.

   Flash Mode DIO. 0 warnings from Momo's code in all builds.

2. ESP32-C3 EMULATOR (QEMU) - the real compiled firmware (test copy without
   Wi-Fi, scripted touches and back-button presses)
     Ran the full script: 1 start, 0 crashes, then the planned wake-up
     restart after "sleep". Free memory flat the whole time: 280,772 bytes
     (lowest 278,016).
     Went through: petting (60 pets, emotion sounds), all 46 expressions,
     Jump, Reaction, Flappy, Simon, Rock paper scissors, Rhythm, every Test
     menu item, hero water and stretch, focus timer, sound off/on, an alarm,
     water and stretch reminders, then the 2.2 part:
       back button hold on the face   -> menu
       back button double-tap         -> "Back" (menu closed)
       hand kept on the head 5 s      -> "Rub! Momo closes its eyes and purrs"
       charger plugged / unplugged    -> "Charging started" / "Charger unplugged"
       battery dropping to 14 %       -> "Battery low" alert
       back button held 3 s           -> "Going to sleep (back button)",
                                         "I'll wake up for the alarm in 2 minutes"
       back button pressed            -> Momo starts again (wake-up)
     The packaged backup simulator firmware (no Wi-Fi, no battery knob) was
     also started in the emulator: boots to "setup finished" and keeps running.
   Emulator limits (not Momo problems, all handled in the test copy):
     - it has no ADC: reading GPIO 4 would wait forever, so the test copy gets
       the battery voltage from the script (Wokwi and the real chip have an ADC);
     - it has no pull-up resistors: GPIO 5 reads "pressed", so the test copy
       gets the button from the script. (This showed a real improvement, now
       in the firmware: a button that is already down when Momo starts is
       ignored until it is let go, so a stuck or shorted button can never make
       Momo sleep again and again - 5 new checks below.)
     - in real-time mode with extra debug printing, two earlier runs hit an
       interrupt watchdog inside the emulator's own interrupt handling. The
       same firmware ran clean in instruction-counted mode (-icount) and in
       real-time mode without the extra printing, so it is counted as an
       emulator timing artefact. Watch the Serial Monitor on the real robot.
